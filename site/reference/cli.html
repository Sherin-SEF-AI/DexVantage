Command-line reference

dexvantage: DexVantage · camera, depth and teleop planning for robot-learning data collection. Every option below is the parser's own, in its groups and order; the worked examples are in the user guide. Installed plugins add their own study flags (dexvantage --help lists them; --no-plugins leaves them out).

dexvantage [PROJECT.dexv | --sample NAME] [OPTION …]

Exit codes

Code Meaning
0 done (validation: every check passed; reproduce: the numbers reproduce; a scorecard: every requirement passes)
1 a failed check, a requirement that does not pass, a result that does not reproduce, an incomplete gather, two projects that differ
2 an error that stopped the run, said in one sentence on standard error (a file that cannot be read, a bad option, a study that cannot work with its inputs)

- as an output writes to standard output. A study flag given a folder (one that exists, or a path ending in /) writes <folder>/<flag>.json.

Positional arguments

Option What it does
path a .dexv project

Options

Option What it does
-h, --help show this help message and exit
--version show program's version number and exit
--self-test check this installation (project file, frames, MuJoCo, OpenCV, fonts, OpenGL, main window, validation) without a window
--theme {dark,light,system} —
--scale SCALE UI scale, e.g. 1.15
--software-3d draw the 3D view with QPainter instead of OpenGL
--sample NAME open a sample project, in the window or in batch mode: so100, ur5e, dexhand, aloha, panda-bimanual, g1
--no-plugins start without loading the installed plugins (Help ▸ Plugins lists them as off)
--list-plugins list the installed plugins, what each added and any error, then exit

Batch mode (no window)

Option What it does
--analyse OUT.json write the project summary study as JSON ("-" for stdout)
--validate OUT_DIR run the validation suite and write its report
--models MODELS with --validate: comma-separated model ids (default: all)
--quick with --validate: fewer Monte Carlo trials (a smoke run)
--reproduce RESULT.json re-run the study that wrote RESULT.json and compare
--tolerance [PATTERN=]VALUE[%] with --reproduce: allowed differences, e.g. 1e-9 or voxels*=0
--synth-episodes OUT_DIR generate synthetic LeRobot episodes with known faults and their ground truth into a new or empty folder (core/sim/episodes.py)
--synth-settings JSON with --synth-episodes: settings as JSON text or a .json file, e.g. {"episodes": 2, "version": "v2.1"}
--dataset PATH with --audit, --plan-vs-recording, --silhouette-calib or --sim2real (or --export with the format fiftyone): the recorded dataset (a LeRobot folder, an RLDS folder or a ROS 2 bag)
--captures DIR with --handeye-solve: a folder of board images to capture at run time; the joint states are its joint_states.csv or .json unless --joints names the file (core/calib/capture.py)
--joints FILE with --captures: the joint_states file (CSV or JSON)
--audit-html OUT.html with --audit: also write the audit report as a standalone HTML page (core/audit/report.py)
--fiftyone OUT_DIR with --audit: also export the per-episode audit scores as a FiftyOne dataset (sample tags and fields; a new or empty folder)
--optimise-settings JSON with --optimise or --design-agent: settings as JSON text or a .json file, merged over the project's, e.g. {"budget": 200, "seed": 3}
--rerun OUT.rrd save the scene for Rerun: the robot over its trajectory, camera frusta, min-Z blind zones, task volumes and, with --audit or --rerun-audit, the audit flags per episode (core/bridges/rerun.py; needs the optional extra rerun)
--rerun-audit AUDIT.json with --rerun: an audit result written before by --audit
--experiment DESIGN.json run a designed experiment (schema dexvantage.experiment/1, docs/models/experiments.md) on the project; writes the result JSON with provenance and the runs as CSV (core/experiments.py)
--experiment-out OUT.json with --experiment: the result file (default DESIGN.results.json beside the design; the CSV goes beside it with .csv)
--export OUT_DIR export the project with --formats (core/exporters); writes each format's files and export_manifest.json (SHA-256 of every file, provenance)
--formats A,B,... with --export: comma-separated export formats, e.g. mjcf,urdf,opencv_yaml,masks,plucker,brackets
--export-options JSON with --export: options per format as JSON text or a .json file, e.g. {"mjcf": {"mode": "snippets"}, "masks": {"atlas": false}}
--check REQUIREMENTS.yaml OUT.json … the readiness scorecard CI gate: evaluate a requirements file ("defaults" for the labelled defaults), print the table and write the JSON with provenance (default scorecard.json); exit 0 pass, 1 fail, 2 error
--reproduce-out REPORT.json with --reproduce: also write the reproduction report (every number compared) as JSON
--run-plan PLAN.json OUT_DIR … run the studies, checks, exports and reproductions a plan lists, in order, and write one JSON summary (core/run_plan.py); outputs go under OUT_DIR (default: the plan's folder)
--diff OTHER.dexv OUT.json … compare the project with another (a .dexv file or unpacked folder): print the changes, write them as JSON to OUT.json; exit 0 same, 1 different
--diff-html OUT.html with --diff: also write the changes as an HTML page
--diff-metrics ID,ID,... with --diff: run these metrics on both projects and give their deltas (core/metric_defs.py lists the ids)
--merge BASE.dexv THEIRS.dexv OUT.dexv three-way merge: the project (ours) and THEIRS, both edits of BASE, written to OUT (a .dexv file or a .dexv.d folder); exit 1 and write nothing when they conflict
--unpack OUT.dexv.d write the project as an unpacked, Git-friendly folder
--pack OUT.dexv write the project (for example an unpacked folder) as a .dexv file
--textconv FILE print a stable text of a .dexv file or folder (a git diff textconv driver: docs/guide/versioning.md)
--cite OUT.bib write BibTeX for every source the project depends on and for DexVantage ("-" for stdout)
--cite-references {checks,all,none} with --cite: the validation references to include (default checks: those the validation checks cite)
--figure SPEC.json OUT.svg write a publication figure (SVG or PDF by the extension) from a figure spec (core/figures.py)
`--figure-width single double
--figure-palette {tol,chart} with --figure: tol (colour-blind safe, default) or chart (the colours in the spec)
--campaign SPEC.json plan a data-collection campaign (schema dexvantage.campaign_spec/1, docs/models/campaign.md) on the project; writes the plan as JSON with provenance, CSV, an iCalendar .ics and a printable HTML (core/campaign.py)
--campaign-out OUT.json with --campaign: the plan file (default SPEC.plan.json beside the spec; .csv, .ics and .html go beside it)
--track RUNS_DIR log every study run, experiment and check of this command as a run in the run store RUNS_DIR (core/tracking; created if missing)
--track-tag TAG with --track (or a project with tracking on): a tag for the runs logged (repeat for more)
--track-note TEXT with --track: a note for the runs logged
--runs-export OUT_DIR export the run store (--track RUNS_DIR, else the project's) as CSV and Parquet tables, an MLflow mlruns/ folder and a W&B replay script
--runs-formats A,B with --runs-export: csv, parquet, mlflow, wandb (default: all four)
--cells CELL … compare several robot cells: .dexv files or folders, or sample:<name>; with a project given, it is the first cell (core/cells.py)
--cells-out OUT.json with --cells: the comparison as JSON ("-" for stdout, the default)
--cells-pooling POOL.json with --cells: the pooling mapping (rename, resize, resample, reorder … per cell, and what cannot be mapped)
--cells-html PAGE.html with --cells: the comparison as a standalone HTML page
--cells-settings JSON with --cells: the study's settings as JSON text or a .json file, e.g. {"reference": 1, "metrics": "all", "tolerance_draws": 16}
--jobs N with --experiment, --experiment-saved, --tolerance-mc, --optimise or --cluster-studies: run in N worker processes on this machine (core/cluster)
--slurm FOLDER with the same: write a Slurm job folder (an sbatch array, docs/guide/cluster.md) instead of running
--shards N with --slurm: the number of array tasks (default: the items, at most 32); with --gather: the shard count when the folder does not record it
--slurm-settings JSON with --slurm: sbatch settings as JSON text or a .json file, e.g. {"mem": "8G", "time": "04:00:00", "partition": "cpu", "activate": "source <venv>/bin/activate"}
--submit with --slurm or --optimise-continue: also submit with sbatch
--cluster-studies LIST.json run a list of (project, study, settings) jobs with --jobs N or --slurm FOLDER
--cluster-out OUT.json with --cluster-studies --jobs: the results file (default LIST.results.json)
--cluster-cache DIR with --jobs or --run-shard: a result cache folder shared by the workers
--run-shard WORK.json run one shard of a cluster work file
--shard I with --run-shard: the shard (0 … N − 1)
--of N with --run-shard: the number of shards
--out DIR with --run-shard: the output folder (default: out/ beside the work)
--gather FOLDER merge a job folder's shard outputs into the result
--gather-out OUT.json with --gather: the result file (default FOLDER/result.json)
--optimise-continue FOLDER the next round of an optimiser job folder on Slurm
--stats SPEC.json statistics and power analysis from a spec (schema dexvantage.stats/1, docs/models/stats.md): compare success counts, samples, two variants over the tolerance Monte Carlo, experiment or tracker runs; the power calculator; writes the result as JSON with provenance
--stats-out OUT.json with --stats: the result file (default SPEC.results.json beside the spec; "-" for stdout)
