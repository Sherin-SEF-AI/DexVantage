Python API reference

import dexvantage as dv gives every name below without importing Qt. The worked examples are in the user guide and The Python and notebook API; this page is the docstrings of dexvantage/api.py, dexvantage/api_research.py, dexvantage/api_cluster.py and dexvantage/plugin_sdk.py, in the order dv lists them.

The module

The Python and notebook API: DexVantage without the window (no Qt is imported on this path).

import dexvantage as dv

rig = dv.sample('ur5e')                          # or dv.open('cell.dexv'), dv.new('My cell')
res = rig.run('coverage')                        # a Result: a dict (the study's JSON) plus .headline, .to_frame()
res.headline['text']                             # 'Task volume seen: 91.9 % (mostly single or blind)'
rig.metrics(['coverage.covered', 'bandwidth.payload_mbps'])
rig.factors['sensor:Overhead D435.z']            # read a factor (core/factors.py paths)
taller = rig.with_factors({'sensor:Overhead D435.z': 1.2})   # a NEW Rig; rig is unchanged
rig.factors['sensor:Overhead D435.z'] = 1.2      # edits rig itself (its project is replaced by the edited one)
rig.export('out/', ['opencv_yaml', 'mjcf'])      # core/exporters: files, notes, a manifest with SHA-256
rig.check('requirements.yaml')                   # the readiness scorecard (core/requirements.py)
rig.save('cell.dexv')
dv.studies(), dv.metrics(), dv.exporters(), dv.plugins()
ds = dv.datasets.open('path/to/lerobot_dataset')  # LeRobot v2.1 / v3.0, RLDS, ROS 2 bags, plugin formats
dv.diff(rig, taller), dv.merge(base, ours, theirs)   # project diff and three-way merge (api_research.py)
dv.bibtex(rig), dv.figure(res, 'fig.svg')        # BibTeX of every source; a vector figure of a result
dv.splat.fit(rig, dataset='episodes/')           # splat views: a 3DGS rig, its held-out quality (api_splat.py)

What edits in place and what returns a new object:

  • rig.factors[path] = value and rig.factors.update({...}) change rig (its project is replaced by the edited copy core.factors.apply returns; Robot and Sensor objects read from it before are then stale).
  • rig.with_factors({...}), rig.use_variant(name) and rig.copy() return a new Rig; rig is unchanged.
  • rig.run(study, **settings) runs on a copy with the settings laid over the stored ones; the rig's stored settings are unchanged (store them with rig.factors['setting:<study>.<key>'] = value).
  • rig.robots, rig.sensors and rig.variants are the project's own objects: changing one changes the rig.
  • rig.add_variant(name, {sensor factors}) adds a copy of the active variant to rig (the active one stays).

Every number comes from the studies themselves (the same code the window and batch mode run, through core.jobs and its result cache, keyed by the project's content): the API computes nothing of its own. A study that cannot run raises DexVantageError (core.jobs.StudyError) with a plain sentence; a figure a result does not state reads None.

Rig and Result have rich HTML views for Jupyter (repr_html). Result.to_frame() returns a pandas DataFrame when pandas is installed (the optional extra "research": pip install "dexvantage[research]"), else a list of dicts (Records) whose .note says so.

Doctest (run by tests/test_api.py):

>>> import dexvantage as dv
>>> rig = dv.sample('so100')
>>> rig
<Rig 'SO-100 sample': 1 robot, 2 sensors, 1 variant>
>>> [s.name for s in rig.sensors]
['Wrist camera (sample placement)', 'Third-person camera (sample placement)']
>>> z = 'sensor:Third-person camera (sample placement).z'
>>> rig.factors[z]
0.36
>>> higher = rig.with_factors({z: 0.5})               # a new Rig
>>> higher.factors[z], rig.factors[z]
(0.5, 0.36)
>>> rig.factors[z] = 0.4                               # edits rig itself
>>> rig.factors[z]
0.4
>>> res = rig.run('bandwidth')
>>> isinstance(res, dict), res['study'], res.headline['word']
(True, 'bandwidth', 'no hosts')
>>> res.headline['text']
'Smallest controller margin: not stated (no hosts). The rig has no host controller: ...'
>>> 'coverage' in [s['id'] for s in dv.studies()]
True

Known limits: the API is a thin layer over the studies, so their own Known limits apply; studies run in the calling thread (the window's background controller is not used: a long study blocks the notebook cell, pass progress= to see it move); the result cache is per process (32 results, keyed by content, so a changed project or setting misses it); UI pages a plugin adds are not reachable from here; HTML views show at most 200 rows of a table.

Find and load the installed plugins again (enabled=False: list them without loading).

dv.runs(where: Rig | str | os.PathLike | RunStore | None = None, *, study: str | list | None = None, tag: str | list | None = None, kind: str | list | None = None, since: str | datetime.date | None = None, until: str | datetime.date | None = None, status: str | list | None = None, project: str | list | None = None) -> Records | pd.DataFrame

The runs of a run store (run_store(where)) as a table: one row per run (run id, start and end in UTC, seconds, kind, study, status, project, its content hash, variant, headline, tags, note, re-run of, DexVantage version, git commit, result hash) and one column per metric (a metric id, or id@stat for a distribution's or a search's figure); None where a run does not state it. A pandas DataFrame (units in .attrs['units']) when pandas is installed, else Records (a list of row dicts, with .units). Filters: study, tag, kind, status, project (a value or a list), since / until (a date, a datetime or ISO text).

dv.track(result: Result | dict, rig: Rig | None = None, *, store: str | os.PathLike | RunStore | None = None, tags: tuple | list = (), note: str = '') -> dict

Log a Result (from rig.run or rig.check) as a run, whether or not the project's tracking is on: into store (a folder or a RunStore; default the rig's project's store). Returns the run record.

dv.run_store(where: Rig | str | os.PathLike | RunStore | None) -> RunStore

The run store (core/tracking/store.py RunStore) of where: a Rig (its project's store), a .dexv project file (the store its tracking settings name, default <name>.runs beside it) or a run store folder.

dv.prices(kind: str | None = None, stated_only: bool = True) -> Table

The library's cited prices: id, kind, device, amount, currency, price kind (maker_store, maker_price_list, reseller), min_quantity, region, source URL and date read; stated_only=False lists the entries without one too (amount None). Nothing is estimated or converted (docs/models/library.md#prices).

dv.price(model_id: str) -> dict | None

The cited price block of one library entry (a copy), or None when the entry states no price.

dv.diff(a: Rig | Project | str | os.PathLike, b: Rig | Project | str | os.PathLike, metrics: str | Sequence[str] | None = None) -> Diff

What changed from a to b (each a Rig, a Project or a path). metrics: metric ids (dv.metrics()) to run on both projects and compare; their studies run in this thread.

dv.merge(base: Rig | Project | str | os.PathLike, ours: Rig | Project | str | os.PathLike, theirs: Rig | Project | str | os.PathLike) -> Merge

Merge two edits (ours, theirs) of one project (base); each a Rig, a Project or a path. Places changed differently on both sides raise dv.MergeConflict (a DexVantageError) whose .conflicts lists them in words.

dv.bibtex(rig: Rig | Project | str | os.PathLike | None, path: str | os.PathLike | None = None, references: str = 'checks') -> str

BibTeX of every source the rig depends on: DexVantage, its library entries' datasheets, its robots' model files, its datasets and the validation references (references: 'checks' those the checks cite, 'all', 'none'). path: also write it there. Returns the text.

dv.figures(result: Result | dict) -> list

The publication figure specs of a study result (a dv Result or its dict), as the paper kit draws them: a list of {'id', 'study', 'spec'}; empty when the result has no per-item list of numbers to chart.

dv.figure(source: Result | dict | str | os.PathLike, path: str | os.PathLike, width: str | float = 'single', palette: str = 'tol', index: int = 0, **options: object) -> dict

Write a vector figure: source is a figure spec (dexvantage.figure/1, a dict, JSON text or a .json file), a {'spec': ...} item of dv.figures(), or a study result (its figure number index). width: 'single' (88.9 mm), 'double' (182 mm) or millimetres; palette 'tol' (colour-blind safe, the default) or 'chart'. The format follows the extension (.svg or .pdf). Returns {'path', 'format', 'width_mm', 'height_mm', 'series'}.

dv.export_runs(where: Rig | str | os.PathLike | RunStore | None, out_dir: str | os.PathLike, formats: str | Sequence[str] = ('csv', 'parquet', 'mlflow', 'wandb'), **filters: object) -> dict

Write the runs of a run store (dv.run_store(where): a Rig, a .dexv file or a store folder) into out_dir as runs.csv / runs_long.csv, runs.parquet, mlruns/ (MLflow's file store layout) and wandb/ (a W&B offline replay), with a manifest (SHA-256 and provenance). filters as dv.runs (study, tag, kind, status, project, since, until). Returns {'files', 'formats': {format: {'status', 'files', 'notes' or 'reason'}}, 'runs', 'manifest'}.

Classes

dv.Rig(project: Project)

A DexVantage project (core.project.Project) seen from Python: its robots, sensors and variants, its factors, its studies, metrics, exports and requirements. Rig(project) wraps a Project; dv.open / dv.sample / dv.new make one.

Rig.add_variant(name: str, factors: dict | None = None, from_variant: str | None = None, allow_locked: bool = False) -> Variant

Add a variant to this rig (edits it, as the window's "New variant from this one"): a copy of from_variant (a name or uid; default the active one) called name, with the sensor factors given set on the copy, e.g. rig.add_variant('Raised overhead', {'sensor:cam_high (overhead).dz': 0.05}). Its sensors keep their uids, so host links, cables and policy cameras apply to it too; the active variant does not change. Returns the Variant (dv.stats.compare_variants(rig, b=name) compares the two).

Rig.apply_sim2real(change: dict) -> Rig

A NEW Rig with one sim-to-real suggestion made (a result's 'apply', or a cause's 'apply'); rig is unchanged. A locked sensor is refused (DexVantageError).

Rig.check(requirements: str | os.PathLike | list | None = None, variant: str | None = None) -> Result

The readiness scorecard: requirements is a requirements file (YAML or JSON), a list of requirement dicts, 'defaults' (DexVantage's labelled defaults) or None (the rig's own). Returns a Result whose headline is the verdict ('ready', 'not ready', 'not evaluated').

The plugin SDK (dexvantage.plugin_sdk)

Plugins: third-party packages that add studies, metrics, exporters, dataset readers, library folders, UI pages and the validation checks of their models to DexVantage without editing it.

A plugin is an installed Python distribution that declares an entry point in the group dexvantage.plugins:

# the plugin's pyproject.toml
[project.entry-points."dexvantage.plugins"]
my_plugin = "my_plugin:register"

# my_plugin/__init__.py
def register(api):                     # api: a PluginAPI, one per plugin
    api.study('my_study', 'My study', batch='my-study')(my_study_fn)
    api.metric('my.figure', 'My figure', 'mm', 'lower', study='my_study')(lambda doc: doc['summary']['mm'])
    api.exporter('my_format', 'My format')(my_export_fn)
    api.dataset_reader('my_format', sniff=my_sniff)(my_open_fn)
    api.library_folder(os.path.join(os.path.dirname(__file__), 'library'))
    api.check('my.vs_closed_form', 'My study against a closed form', 'mm error', 'the closed form',
              0.01, 'mm', references={'me2026': 'A. Author, "Title", URL (read 2026-11-07).'})(my_check_fn)
                                       # a validation check of the plugin's model (plugin.my_plugin), run by
                                       # --validate and Help ▸ Validate the models with the built-in checks
    api.page('my_page', 'My study', 'my_plugin.page:MyPage', menu='Analysis')   # the class is imported only
                                                                                 # when the window is built

The entry point may name a function or a module (its register is called). DexVantage loads plugins once at start-up (app.py, before the batch flags are built, so a plugin study gets its --flag too), and the Python API loads them on first use (dexvantage.api). Help ▸ Plugins lists every plugin found: its name, version, what it added and, for a plugin that failed, why, in a plain sentence. A plugin that fails is rolled back (what it added before the failure is removed) and the app carries on; its traceback goes to the log (stderr), never to the UI.

--no-plugins (or the environment variable DEXVANTAGE_NO_PLUGINS=1) finds the installed plugins without loading them: they are listed as "off".

Rules a plugin follows (checked where they can be): ids are new (a plugin cannot replace a built-in study, metric, exporter or dataset format: the duplicate is skipped and said so); study ids are lower-case words joined by underscores (no dots: factor paths and settings use the dot); a page class is given as "module:Class" so headless use never imports Qt; a plugin's figures follow docs/DEVELOPING.md like DexVantage's own (cited or None). A plugin may set REQUIRES_API = n in its module; one that needs a newer plugin API than API_VERSION is refused with a sentence.

API load(enabled=True, entry_points=None, paths=None) -> [PluginRecord] once; again with reload=True loaded() -> [PluginRecord] what the last load found (for Help ▸ Plugins and dv.plugins()) discover(paths=None) -> [EntryPoint] the installed entry points of the group (paths: search there) unload(name) remove what a plugin added (tests; a plugin turned off) origin(kind, id) -> plugin name | None which plugin added a study / metric / exporter / reader / page / check summary_text(record) -> str "2 studies (a, b), 1 metric (c)": what it added, in words

Known limits: a plugin runs in the same process with the same rights as DexVantage (there is no sandbox: install only plugins you trust); unloading removes what a plugin registered, not modules it imported or state it changed in other ways; UI pages are added when the window is built, so a plugin loaded later (from the Python API in a running window) adds its page only after a restart; a page whose id equals a built-in page's id is replaced by the built-in one (the plugin's record says so: page_replaced).
